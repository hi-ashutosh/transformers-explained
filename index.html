Convert tokens into learned vectors. Add a signal that tells the model where each token sits in the sequence.

Gather and transform context

Attention mixes information between positions. A feed-forward network transforms each position’s features. Residual connections and normalization support the computation.

Learn to predict

Turn the final representation into next-token probabilities. During training, errors update the parameters. During generation, the parameters stay fixed and the sequence grows.

02 / The building blocks

Keep the whole block in view.

Tokens and embeddings

A tokenizer defines the discrete symbols the model reads. Each token ID selects a learned vector. Repeated tokens share that lookup vector; their contextual representations can differ later.

Position information

Tokens need information about sequence order. This demo adds the original sinusoidal position signal to scaled embeddings. In the Tokens view you can inspect both parts separately.

Queries, keys, and values

Three learned projections provide three views of the current representations. Queries and keys produce compatibility scores. Attention probabilities weight the value vectors that get combined.

Multiple attention heads

Different projections allow several context mixtures in parallel. The results are concatenated and projected back to the model width. The model learns their uses; “one head = one grammatical role” is not a design rule.

Residual connections and normalization

A residual connection adds a sublayer’s result to its input. Layer normalization operates across the features of each token, with learned scale and shift. Our block follows the original paper’s post-normalization layout.

A position-wise feed-forward network

Two learned linear transformations with a nonlinearity between them transform each position separately. Attention provides the mixing between tokens; this sublayer adds further expressive power within each token’s representation.

A full model stacks many blocks. The toy uses one block, two heads, and eight features so every value fits on screen. Many modern implementations change details such as normalization placement or positional encoding; the original architecture is our reference here.

Parallel training. Sequential generation.

The current training example is “.” Its input is shifted by one position relative to its targets. The causal mask lets every row predict its next token without reading the answer from a later input position.

What changes during learning?

The training objective rewards probability assigned to the observed next token. Backpropagation computes gradients through the readout, feed-forward network, attention, and embeddings; an optimizer updates their parameters.

The supplied NumPy implementation trains this entire tiny model. The curve below records that actual training run. The browser loads its weights and computes the forward pass; it does not retrain a network when you click a token.

Some prefixes are ambiguous: after “the,” the training data allows three different animals. A correct model should keep uncertainty there, so the best achievable average loss is greater than zero.

What changes during generation?

The parameters stay fixed. Take the final position’s distribution, choose or sample one token, append it, and repeat. Try the Generate button. END means that the model has finished the sentence.

04 / The original Transformer

How this connects to the classic paper.

Vaswani et al., Attention Is All You Need (2017) introduced an encoder–decoder Transformer for sequence transduction, including translation. The interactive model above focuses on a causal decoder block so next-token prediction stays easy to follow.

The encoder: represent the source

Source token embeddings + positions
↓
Unmasked self-attention
Residual connection + LayerNorm
Position-wise feed-forward network
Residual connection + LayerNorm
↓ repeat encoder blocks
Contextual source representations

Each source position can read the whole source sequence. Encoder outputs become the memory supplied to the decoder’s cross-attention.

The decoder: generate the target

Shifted target embeddings + positions
↓
Causally masked self-attention
Residual connection + LayerNorm
Cross-attention to encoder outputs
Residual connection + LayerNorm
Feed-forward → residual + LayerNorm
↓ repeat decoder blocks
Vocabulary logits → next-token probabilities

Cross-attention takes queries from the decoder and keys/values from the encoder’s output. A decoder-only model omits this encoder-memory sublayer and generates from its own context.

These are architecture diagrams, not a second trained translation model. The original paper uses six encoder layers and six decoder layers. Our single-block model uses the same scaled dot-product attention and post-normalization conventions, with a much smaller width.

The feed-forward widths are 8o16o88 o16 o88o16o8. Its parameters are shared across positions. LayerNorm computes mean and variance over the eight features within each row, then applies a learned scale and shift. Those affine parameters mean its final output need not have zero mean or unit variance.

This is the original post-normalization ordering. Many later architectures use pre-normalization instead. The tiny model omits dropout to keep the numerical trace deterministic.

The loss is evaluated at each training position and averaged over the batch and positions. Backpropagation differentiates it through all learned parts of the model. At inference, no gradient update is needed.

The generation-temperature control changes the sampling distribution over the output vocabulary. It is separate from attention’s dk\sqrt{d_k}dk​​ scaling. Taking the most probable token and sampling from the distribution are different decoding choices.

6. What grows with the context length? The cost of pairwise attention

For each head, a full attention map has n×nn\times nn×n entries. Longer contexts therefore increase the size of the conventional attention matrix quadratically. The feed-forward part also contributes substantial computation. This teaching implementation favors inspectability; it does not include efficient attention kernels or a generation cache.

06 / Code & provenance

Small enough to inspect, real enough to test.

The website computes the model in plain JavaScript. The weights were trained with NumPy on the six sentences listed in model.json. That narrow dataset supports this lesson; it is not a general-purpose language model.

# A causal decoder block, omitting batching notation
x = scaled_token_embeddings + positional_signal
q, k, v = project(x)
a = softmax(q @ k.T / sqrt(head_width) + causal_mask)
context = concatenate_heads(a @ v) @ output_projection
y = layer_norm(x + context)
z = layer_norm(y + feed_forward(y))
next_token_probabilities = softmax(z[-1] @ readout + bias)

# Training: compare each position with its shifted next-token label.
# Generation: choose a token, append it, and run the model again.
